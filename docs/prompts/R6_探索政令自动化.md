## 硬约束（违反即返工）

1. **完全 Godot 4.4 + GDScript 静态类型，零 Java**；全仓库无 Java。
2. **服务端权威、客户端零规则**：客户端**不实现任何成功率/冷却/槽位/阈值计算**；「能不能探、成功率几何、槽位够不够」一律来自 `queryJiYuanInfo`/`queryMiJingInfo`/`queryPolicyOptions`/`queryAutomationState` 回包。

4. **业务失败 ≠ 协议失败**：冷却未到、灵石不足、参与者超上限、政令槽位不足、时代未到、道法未解锁等一律 `ok:true + result.success:false + result.message`；只有参数缺失/枚举非法（如 `setAutomationToggle.key` 不在 `improve/repair/road/explore`）才 `BAD_PARAMS`。
5. **相机铁律**：锁 45° 正交、禁旋转；探索、政令、自动化开关、集结/回防、结束回合、任何 view 刷新后，`CameraRig` 的 transform 与 `size` 都**不得重置**。
6. **确定性**：同种子 + 同指令序列，任意次数跑结果逐字一致；**所有随机只经 `RngService`**（探索成败、秘境富裕/险情、伤亡/陨落、自动项目选择）。
7. 新增 `class_name` 后必须对两工程分别 `--import`；任何 Agent 跑通后无残留 godot 进程。
8. 表现层只读 `view`；R6 只用占位资源，不做真美术/转场粒子（R8）。
9. `setSetting` **只确认、值留客户端**（`applied:false`），**服务端不改 `GameState`、不回 view**（PROTOCOL §7 明列）。
