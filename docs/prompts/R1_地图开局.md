## 硬约束（违反即返工）

1. **完全 Godot 4.4 + GDScript 静态类型，零 Java**；全仓库无 `.java`。
2. **规则、数值唯一权威是 `data/gameConfig.json` 与服务端 `rules/`**：客户端不实现任何玩法规则。新增地形块的数值**只能照抄 §4.1.10 设计初值**，不得自行发挥。
3. **2.5D 硬约束**：3D 低模/占位 + **正交投影相机锁定 yaw=45°、pitch=45°，禁止旋转、禁止自由环绕**；任何操作、动画、收到 view 快照后相机角度与缩放都**不得重置**。
4. 表现层只读 `view`，不推导规则；迷雾可见集合由服务端下发。
5. R1 只用占位模型/纯色材质（AssetLibrary 缺失回退），**不做正式美术、不做动画粒子**（转场/昼夜在 R8）。
6. 地图生成必须**确定性**：同种子、同宽高，任意次数跑出来的地图逐字一致。
7. 无残留 godot 进程。

## 服务端任务（`server/scripts/`，只在权威层）

- `rng/RngService.gd`：集中随机源（`RandomNumberGenerator`，种子来自 `newGame`；记录调用序号）；**所有**随机只经此，禁止各处私自 new。
- `model/`：枚举（境界/站位/灵根/派系/节点类型/基底/海拔/地貌/建筑/区域/改良/兵种/指令/资源）、`HexTile`（含 §6.5 全部新字段：`baseTerrain,relief,features[],riverEdges[],danger,ownerSectId,nodeId,districtId,workedByPeakId,improvementId,luxuryType`）、`GameNode`、`Sect`、`Disciple`、`SpiritPeak`、`GameState`。
- `rules/MapGenerator.gd`，分层生成（§4.1）：
  1. 基底（灵田/灵壤/荒土）；
  2. 海拔，用**连续山脊噪声**生成丘陵/山岳（不要单点孤立），保证出现**连绵多格山脉**；
  3. 地貌（灵林/雾泽，山岳顶不叠）；
  4. 河流：从山岳/丘陵起源、向低海拔连续流到地图边缘，**河流是地块边**（成对边标记），每个起源 1–2 个连续边；
  5. 险地、节点（按地形偏好）、奢侈资源；
  6. 出生点：中心玩家 + 3 个方向 AI；出生点附近保证安全（无险地、无山岳封死、可走通、有近水/灵田资源，按 §4.1.10/§4.3）。
- `rules/SetupInitializer.gd`：4 宗（1 玩家 + 3 AI）；每宗 1 主峰（人口 3/容量 10/防御 10）、1 名金丹宗主 + 2 名炼气外门弟子；初始资源灵气 400/灵石 300/工力 120/声望 0 + 天晶 2/玄铁 2/灵木 4。
- `rules/VisionCalculator.gd`：按视野半径（灵峰 3、节点 2；弟子 炼气 2/筑基 2/金丹 3/元婴 3/化神 4；站丘陵 +1）算每宗 `visibleTiles`/`exploredTiles`（R1 开局初始视野；随回合重算在 R2）。
- 命令：`newGame`（params：`mapWidth/mapHeight/randomSeed/difficulty/sectName/factionType`，见 §6.1）、`getState`；`StateView` 构造 §6.5 视图（含 tiles 新字段、nodes、sects、disciples、spiritPeaks、visible/explored、当前玩家视角的迷雾）。
- 无 `relations/lairs/disasters`（已裁剪）。

## 客户端任务（`client/`，只表现）

- `shared/geo/hex.gd`（共享）：flat-top 六边形轴向坐标、六邻接、**世界坐标**（x 按 size*1.5*q、z 按 size*√3*(r+q/2)，以实际文档/实现为准），以及由 `relief` 柱高系数（1.0/1.7/3.0）得到的柱体高度与顶面落点；纯函数无状态。
- `scripts/art/AssetLibrary.gd`：读 `assets/manifest.json`（schemaVersion 3），按逻辑 ID 懒加载 `.glb`/`.png`/`.tres`；**缺失回退占位**（模型=灰阶几何体+文字标签，贴图=纯色块，打印 WARN），不崩溃。
- `scripts/world/HexMap.gd`（Node3D）：
  - 每格一个六棱柱（`CylinderMesh` radial_segments=6，顶面朝向对齐 flat-top，以相邻格无错位为准）；侧面按海拔拉伸（柱高系数），顶面贴基底色块；MOUNTAIN 用最高柱 + 峰顶，相邻 MOUNTAIN 视觉连成**连绵山体**。
  - 地貌占位：灵林=小锥/小树群、雾泽=半透明青灰片；河流=贴边的蓝色 ribbon/细盒（严格落在地块边，成对）；险地=印记贴片；节点=带标签的小模型占位。
  - 地块按 海拔/地貌/河流/节点/单位/迷雾 分层（节点与单位位于对应顶面，不悬空）。
- `scripts/world/Fog.gd`：三态遮盖（§4.2）——未探索=宣纸空白（米白占位）、已探索无视野=水墨古图（灰排线占位，无单位）、视野内=正常实景；R1 静态切换，不做泼墨动画。
- `scripts/world/CameraRig.gd`：
  - `Camera3D`，`projection=PROJECTION_ORTHOGONAL`；固定看向地图中心，yaw=45°、pitch=45°（启动即定，不暴露任何旋转输入）。
  - 滚轮=以鼠标射线地面交点为中心缩放（改 `size`）；中键/右键=拖拽平移；**禁用旋转**。
  - 相机为常驻/自动加载节点，`view` 刷新或任何操作只更新地图内容，**不重建、不重置 transform 与 size**。
- `scripts/world/UnitView.gd`/`SectView.gd`：用占位几何体表现弟子/主峰，按宗门色区分；位置取服务端坐标。
- `scenes/MainMenu.tscn` + `ui/MainMenu.gd`：选流派（宗门/家族/国家）、难度、宗门名、地图宽高（默认 20×15）、随机种子（可空=随机）；开始 → 发 `newGame` → 切 `scenes/World.tscn` 渲染 view。
- `scenes/World.tscn`：HexMap + Fog + CameraRig + 极简侧栏（选中格列出 基底/海拔/地貌/河流/险地/节点/资源/归属，作为 UI 直观化的最小验证，正式面板在 R8）。

## 自动验收（扩展 `tools/check.ps1`，全部通过）

服务端（无头）：
1. 固定种子（如 `123456`）跑两次 `newGame`，导出两份 view 的 tiles 全字段（`baseTerrain/relief/features/riverEdges/danger/nodeId/luxuryType/ownerSectId...`），**逐字一致**。
2. 统计：MOUNTAIN≈8%、HILL≈22%（±3% 容差）；每条河流边成对、连续、从高到低至边界；至少有一条**连绵 ≥3 格**的山脉；出生点中心及三方向附近无险地、无山岳封死、可走通；节点只出现在偏好地形。
3. view 含 §6.5 新字段；响应中不含 `relations/lairs/disasters`。
4. 初始 4 宗、每宗 1 主峰 + 1 金丹宗主 + 2 炼气外门、资源为 400/300/120/0 与 晶2/铁2/木4。
5. 玩家 `visibleTiles`/`exploredTiles` 与视野半径一致（峰 3、弟子 2，丘陵 +1）；未可见敌方单位不下发。

客户端（GUI，人工/截图断言）：
6. 柱体高度 FLAT<HILL<MOUNTAIN，山岳连绵；河流沿边、地貌与基底配色正确、险地有印记。
7. 三态迷雾：未探索=米白、已探索=灰、可见=实景；迷雾范围与服务端集合一致。
8. 鼠标尝试任何旋转操作**无效果**，相机角度恒为 45°；缩放（以鼠标为中心）与平移正常；执行「再开一局/收到 view 刷新」后角度与缩放保持不变。
9. 主菜单能传参开局，成功进入地图并渲染 4 宗。

通用：
10. 无 `.java`；退出后无残留 godot 进程；占位资源缺失只 WARN 不崩溃。
