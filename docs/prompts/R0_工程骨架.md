## 硬约束（违反即返工）

1. **完全 Godot 4.4 + GDScript（静态类型），零 Java、零 JVM**：全仓库不得出现 `.java`，不得调用任何外部语言运行时（除 Godot 自身）。
2. **服务端权威、客户端零规则**：R0 只允许 `ping`；不要提前实现任何地图/战斗/经济逻辑。
3. 全部 GDScript 写类型注解（`var x: int`、`func f(a: String) -> Dictionary:`）；命令名、协议常量、枚举只允许引用 `shared/protocol/`，禁止散落字符串。
4. 两个工程目录物理隔离：`client/` 不得 `load()` 任何 `server/` 脚本；两端共享的只有 `shared/`（经 junction 挂载）。
5. 数值/端口/版本号一律走配置或常量，不硬编码在业务脚本里。
6. 服务端必须能在 `--headless` 下无报错运行；stdout/日志干净，不污染消息帧。
7. 结束后**不得残留任何 godot 进程**（验收脚本负责清理，你自己也要确认）。

## 要创建的文件（按此清单，不增不减）

> **命名约定：GDScript 文件名一律 PascalCase**（`ServerMain.gd`、`NetServer.gd`、`CommandDispatcher.gd`…），与 `class_name` 一致。

### 共享层 `shared/`
- `shared/protocol/commands.gd`：命令名常量（`class_name Commands`，`PING="ping"`，其余里程碑再加）。
- `shared/protocol/msg.gd`：协议常量（`PROTOCOL_VERSION="2.0"`、`SAVE_VERSION="3.0"`、`BACKEND="xiuxian-godot-headless"`、`DEFAULT_HOST`/`DEFAULT_PORT=9527`）、消息类型（`TYPE_HELLO`）、信封/hello 字段名常量（`KEY_*`）、错误码字符串常量（`ERR_*`：`BAD_JSON/NO_ID/BAD_REQUEST/UNKNOWN_COMMAND/NOT_IMPLEMENTED/BAD_PARAMS/NO_GAME/INTERNAL`）。
- `shared/protocol/enums.gd`：占位（R0 留空框架并加注释，后续里程碑填枚举）。
- `shared/protocol/dto.gd`：静态类型的信封解析/构造辅助（`hello()`、`ok_response()`、`error_response()`、`parse_text()`；**不解析未知字段、不做玩法**）。
- `shared/geo/hex.gd`：仅放 `const` 占位与注释（轴向/世界坐标 R1 实现），R0 不要写地图逻辑。

### 服务端 `server/`
- `server/project.godot`：Godot 4.4 项目；主场景 `res://scenes/ServerMain.tscn`；应用名 `xiuxian-server`。
- `server/scenes/ServerMain.tscn` + `server/scenes/ServerMain.gd`：根 `Node`，`_process` 驱动网络循环；启动打印一行 `server listening on 127.0.0.1:9527`；配置加载失败以非零码退出。
- `server/scripts/net/NetServer.gd`（`class_name NetServer`）：
  - `TCPServer.listen(9527, "127.0.0.1")`；每帧 `take_connection()` → `WebSocketPeer.new()` → `accept_stream(stream)`。
  - 维护连接列表，每帧对每个 peer `poll()`、按 `get_ready_state()` 处理 OPEN/CLOSED；用 `get_packet_count()`/`get_packet()` 取文本帧（UTF-8）。
  - 新连接 OPEN 后**第一条**主动发 `hello`（由 `ServerMain` 用 `Dto.hello(implemented_commands)` 构造）。
  - 用 `send_text()` 发送紧凑 JSON（帧内不得出现裸换行）。
- `server/scripts/net/CommandDispatcher.gd`（`class_name CommandDispatcher`）：
  - 分发：`ping` → `{"id":<回显>,"ok":true,"events":[],"result":{"pong":true}}`（不带 view）。
  - 错误码：非合法 JSON→`BAD_JSON`；缺 `id`→`NO_ID`；缺/非字符串 `type`→`BAD_REQUEST`；未登记命令→`UNKNOWN_COMMAND`（`id` 能回显就回显）。
  - `implemented_commands()` 供 `hello` 使用；顺序处理。
- `server/scripts/config/ConfigLoader.gd` + `ConfigValidator.gd`：
  - 定位并读取 `data/gameConfig.json`（用 `--data` 传入路径，缺省为工程目录上一级的 `data/gameConfig.json`）。R1 才放全量，**R0 允许读最小占位文件**。
  - 读不到/JSON 非法 → 明确报错并**以非零码退出**，不许静默。
- `data/gameConfig.json`（R0 最小占位）：`{ "schemaVersion": "3.0", "meta": { "note": "R0 placeholder, full config migrated in R1" } }`。
- `server/tests/SmokeTest.tscn` + `server/tests/SmokeTest.gd`：headless 自测客户端（见验收）。

### 客户端 `client/`
- `client/project.godot`：Godot 4.4；主场景 `res://scenes/Main.tscn`；应用名 `xiuxian-client`。
- `client/scenes/Main.tscn` + `client/scenes/Main.gd`：显示「连接状态」「hello 各字段」「Ping 按钮」「回包日志」；启动自动连接。
- `client/scripts/net/NetClient.gd`（`class_name NetClient extends Node`）：
  - `WebSocketPeer.new()` + `connect_to_url("ws://127.0.0.1:9527")`；每帧 `poll()`；连接建立后等待 `hello`，解析后发信号给 UI。
  - `send_command(type, params) -> String`（返回 `c<N>` 序号）；按 `id` 匹配响应。
  - 首连失败自动重试（指数退避，上限后提示）；R0 不做复杂断线重连。
- `client/scripts/net/Launcher.gd`（`class_name Launcher`）：
  - 解析顺序：环境变量 `GODOT_CONSOLE_EXE` → `tools/godot_path.txt`（不入库）→ 固定路径 `C:\Users\Administrator\godot\Godot_v4.4.1-stable_win64_console.exe`；用 `OS.create_process(...)` 以 `--headless --path <abs server> -- --port=... --data=...` 拉起服务端，记录 PID。
  - 客户端退出时 `OS.kill(pid)` 关闭自己拉起的子进程。

### 工具 `tools/`
- `tools/setup_shared.ps1`：把顶层 `shared/` 以**目录联接 Junction**（`New-Item -ItemType Junction`）挂到 `client/shared` 与 `server/shared`；已存在则跳过/重建；**幂等**。
- `tools/run_dev.ps1`：先拉起 headless 服务端（console 版）再启动客户端（GUI 版），结束时清理。
- `tools/check.ps1`（R0 自检，见下）。

### `.gitignore`
- 追加忽略：`client/shared/`、`server/shared/`（Junction 本体）、各工程 `.godot/`、`*.tmp`、`*.uid`（Godot 4.4 引擎元数据）、`tools/godot_path.txt`、导出产物。顶层 `shared/` 真实目录要正常入库。

## 握手与消息契约（严格按 §6）

服务端首帧（连接建立即发）：
```json
{"type":"hello","protocolVersion":"2.0","backend":"xiuxian-godot-headless","saveVersion":"3.0","implementedCommands":["ping"]}
```
请求：
```json
{"id":"c1","type":"ping"}
```
成功响应：
```json
{"id":"c1","ok":true,"events":[],"result":{"pong":true}}
```
失败响应：
```json
{"id":"c1","ok":false,"errorCode":"UNKNOWN_COMMAND","message":"..."}
```

## 自动验收（`tools/check.ps1`，必须全部通过）

1. 运行 `setup_shared.ps1`，断言 `client/shared` 与 `server/shared` 均是指向顶层 `shared/` 的**目录联接**（ReparsePoint），并**在 `client/shared` 建临时文件、断言 `server/shared` 与顶层 `shared` 双向可见**，测后删除。
2. 两个工程各跑一次 `--headless --path <proj> --import`，断言**无解析错误**且生成 `global_script_class_cache.cfg`。
3. **负向用例**：指向不存在的配置启动服务端，断言**非零退出码**且输出可诊断原因。
4. 用 console 版 `--headless --path server -- --port=9527 --data=<abs>` 启动服务端，**TCP 轮询**确认 30 秒内监听 `127.0.0.1:9527`。
5. 用 console 版 `--headless --path server res://tests/SmokeTest.tscn -- --port=9527` 跑无头自测，它必须：
   - 连上 `ws://127.0.0.1:9527`，收到 `hello`，断言 `protocolVersion=="2.0"`、`saveVersion=="3.0"`、`backend`、`implementedCommands` 含 `ping`；
   - 发 `ping`，断言回包 `ok==true`、`id` 回显、`result.pong==true`；
   - 发未登记命令，断言 `ok==false` 且 `errorCode=="UNKNOWN_COMMAND"`；
   - 发缺 `id` 的帧，断言 `errorCode=="NO_ID"`；
   - 全部通过打印 `SMOKE_PASS` 并退出码 0，否则 `SMOKE_FAIL` 退出码 1。
6. 清理所有由本脚本/客户端启动的 Godot 进程（按 PID 或匹配命令行），最终不残留本次拉起的 godot。
7. 扫描仓库确认**无 `.java` 文件**。
